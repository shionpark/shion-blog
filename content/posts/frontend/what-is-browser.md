# **브라우저란 무엇일까요?**

구글 크롬, 파이어폭스, 인터넷 익스플로러 등은

월드 와이드 웹(World Wide Web)에 존재하는 콘텐츠를 찾아, 검색하고, 표시하는 데 사용되는 **응용 소프트웨어 프로그램**입니다.

***그런데 왜 이런 프로그램이 필요할까요?***

그 이유는 인터넷에서 오가는 것이 단순한 텍스트 데이터(HTML, CSS, JS, JSON, XML 등)일 뿐이기 때문입니다.

즉, 사용자가 원하는 정보를 요청하면 브라우저가 해당 데이터를 찾아 해석하고,
이를 웹 페이지, 버튼, 이미지, 동영상처럼 **사람이 쓸 수 있는 형태**로 바꿔주는 것입니다.

이 과정을 **렌더링(Rendering)**이라고 부릅니다.

# **어떻게 동작하나요?**

## **1. URL 입력**

모든 서버는 고유한 **IP 주소**를 가지고 있습니다. (예: `3.34.220.186`)

하지만 사람이 모든 IP를 외우는 것은 어렵기 때문에, 도메인 주소(예: `channy.creation.net`)를 사용합니다.

브라우저는 사용자가 입력한 URL을 DNS(Domain Name System)에 조회해 해당 IP 주소를 찾아냅니다.

## **2. 서버와 통신**

브라우저는 요청을 **패킷(Packet)**이라는 단위로 만들어 보냅니다.

편지 봉투에 발신인/수신인 주소와 내용을 담아 보내는 것과 비슷합니다.

이때 인터넷은 **TCP/IP 프로토콜**을 따릅니다.

- **IP**는 패킷에 목적지 주소를 붙이고,
- **TCP**는 누락된 패킷을 재전송하거나 순서를 맞추어 안전하게 전달되도록 합니다.
> **패킷의 이동 경로: 우리집 → 공유기 → ISP 장비**

- 집 공유기: 가정용 라우터 (집 내부의 사설 IP ↔ 공인 IP 변환, NAT 기능)
- ISP 장비: 통신사 데이터센터에 위치한 대형 라우터 (더 큰 인터넷 망으로 연결)
라우터는 네트워크의 길 안내 네비게이션과 같습니다.

“이 IP 주소는 이쪽 경로로 보내야겠다” 하고 패킷을 다음 경로로 넘겨주며,

이 과정을 반복하면서 서버에 가까워집니다.

## **3. 패킷 안에 담긴 HTTP 메시지**

브라우저가 실제로 작성하는 요청 메시지는 **HTTP/HTTPS 프로토콜**을 따릅니다.

이 메시지가 여러 계층을 거쳐 포장되어 서버까지 전달됩니다.

- **응용 계층 (HTTP)**: 요청 규칙 정의 (GET /index.html HTTP/1.1)
- **전송 계층 (TCP)**: HTTP 메시지를 세그먼트로 분할
- **네트워크 계층 (IP)**: 출발지/목적지 IP 주소를 붙여 패킷으로 포장
- **데이터 링크 계층 (Ethernet/Wi-Fi)**: 패킷을 전기 신호/무선 신호로 변환해 전송
브라우저와 서버는 먼저 **3-way handshake**로 연결을 확인한 뒤,

HTTP 요청 → 응답 순으로 데이터를 주고받습니다.

## **4. 응답 받기**

서버는 브라우저가 요청한 **HTML, CSS, JS, 이미지, JSON 데이터** 등을 응답합니다.

## **5. 렌더링(Rendering)**

브라우저는 **Critical Rendering Path**를 따라

- HTML 파싱 → DOM 생성
- CSS 파싱 → CSSOM 생성
- DOM + CSSOM 결합 → Render Tree 생성
- Layout → Paint 과정을 거쳐 화면을 그립니다.
## **6. 자바스크립트 실행**

마지막으로 브라우저의 자바스크립트 엔진(V8, SpiderMonkey 등)이 응답받은 JS 코드를 실행합니다.

이를 통해 웹 페이지는 정적인 문서를 넘어, 동적인 UI와 사용자 경험(UX)을 제공하게 됩니다.
