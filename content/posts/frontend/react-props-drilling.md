프롭 드릴링은 부모 컴포넌트의 데이터를 자식에게 넘길 때 중간에 있는 여러 컴포넌트를 거치는 방식이다. 중간 컴포넌트는 값을 쓰지 않고 전달만 한다. 계층이 깊어지면 데이터 흐름을 따라가기 어렵고, 전달만 하는 컴포넌트가 불필요하게 복잡해진다.

흔한 대안은 두 가지다. Context API로 Provider를 만들어 중간 컴포넌트를 건너뛰고 데이터를 주거나, Redux, Recoil 같은 상태 관리 라이브러리로 상태를 한곳에서 관리한다.

## 개인적인 생각

‘꼭 프롭 드릴링을 지양해야 하는가?’라는 질문에 나는 ‘그럴 수도 있고 아닐 수도 있다’라고 대답할 것이다. 프롭 드릴링은 간단한 데이터 전달에는 유용한 방법이지만, 복잡한 애플리케이션에서 상태 관리가 비효율적일 수 있다.

### 프롭 드릴링의 장점

프롭 드릴링으로 값을 전달하면 어디서 데이터가 쓰이는지 그대로 보인다. 각 컴포넌트가 어떤 프로퍼티를 받아 쓰는지 확인할 수 있어서 코드의 의도를 파악하기 쉽다. 팀 프로젝트에서 여러 개발자가 같이 작업할 때 특히 그렇다. 값의 흐름을 쉽게 추적할 수 있어서 디버깅이나 코드 변경도 편하다. 특정 값이 잘못 전달됐을 때 어떤 경로로 왔는지 바로 따라갈 수 있다.

실제로 프로젝트에서 3~4단계 계층까지는 프롭 드릴링으로 기능을 구현하려고 했다. 수정이 필요한 코드를 빠르게 파악하고 유연하게 대처할 수 있었다.

## 정리

프롭 드릴링은 단점이 있어도 데이터 흐름이 보인다는 장점이 있다. 그래서 상황에 따라 쓰고, 필요할 때 Context API나 상태 관리 라이브러리를 쓰는 게 좋다고 생각한다.
