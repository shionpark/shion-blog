## 1. 프로젝트 소개

Fitness Manager(가명)은 헬스장 운영을 위한 맞춤형 B2B CRM 서비스이다.

기존 수기 문서 기반의 비효율적인 운영 환경을 개선하고자 기획되었으며, **매출 정산, 통계 분석, 전자 계약** 등 헬스장 업무에 특화된 고유 로직을 구현할 수 있도록 설계되었다.

단순한 회원 관리 시스템을 넘어, **회원–직원–지점** 간의 복잡한 권한 체계를 반영한 구조와 실무 중심의 기능들이 통합된 커스터마이징 가능한 플랫폼이다.

## 2. 역할 기반 접근 제어 (RBAC)

사용자에게 직접 권한을 부여하지 않고, 실제 조직의 직책(Role)을 기준으로 미리 정의된 권한을 가진 역할만을 부여하는 역할 기반 접근 제어(RBAC, Role-Based Access Control) 방식으로 시스템을 설계했다.

| **역할** | **설명** |
| --- | --- |
| 관리자 | 전체 시스템 접근 (직원/지점/통계/회계 관리 포함) |
| 매니저 | 지점 단위 관리 (직원/팀 관리 및 지점별 통계 확인) |
| 팀장 트레이너 / 팀장 FC | 실무자(트레이너/FC) 팀 관리 |
| 트레이너 | 담당 회원 수업 및 출석 관리 |
| FC | 락커 배정, 회원 응대 |
| 아르바이트 | 실무 보조 (권한 제한) |

> 역할은 단지 UI 렌더링에만 영향을 주는 것이 아니라, **실제 API 접근 제어의 기준**이 되며, 사용자와 자원의 관계를 명확히 구분해준다.

## 3. **메뉴 구조와 권한 기반 분기**

서비스의 주요 기능은 두 가지로 나뉜다:

- **공통 메뉴**: 모든 직원이 접근 가능
- **사용자 메뉴**: 역할에 따라 동적으로 렌더링 및 제한
```bash
메뉴 구조/
├── 공통 메뉴 (모든 직원 접근)
│   ├── 대시보드
│   ├── 공지사항
│   ├── 회원 관리
│   ├── 상품 관리
│   ├── 락커 관리
│   └── 출석 관리
│
└── 사용자 메뉴
    ├── 관리자 (전역 권한)
    │   ├── 직원 관리
    │   ├── 팀 관리
    │   ├── 통계 관리
    │   ├── 회계 관리
    │   └── 지점 관리
    │
    ├── 매니저 (지점 운영)
    │   ├── 직원 관리
    │   ├── 팀 관리
    │   ├── 통계 관리
    │   └── 회계 관리
    │
    └── 트레이너
        └── 나의 업무 (회원 수업, 출석)
```

메뉴 구성은 Dictionary 기반으로 정의하고, 로그인 시 Recoil에 저장된 사용자 역할을 기준으로 조건부 필터링하여 화면에 렌더링한다.

## 4. **이중 접근 제한 전략**

UI 상에서 메뉴를 숨기더라도 사용자가 직접 URL을 입력하거나 API를 호출할 수 있기 때문에, **백엔드에서도 동일한 권한 검사**가 적용되어야 한다.

예시) 지점 상세 정보 요청

- **관리자**: 전체 지점의 상세 정보 조회 가능
- **매니저 이하**: 지점 이름, ID, 코드 등 최소 정보만 조회 가능
즉, 프론트에서는 조건에 따라 API 호출을 막고, 백엔드는 호출이 들어와도 403 Forbidden 응답을 반환하는 **이중 제한 전략**을 채택했다.

## 5. 최소 권한 원칙 (PoLP)

권한 설계는 **업무 수행에 필요한 최소한의 권한만 부여**한다는 PoLP(Principle of Least Privilege) 원칙에 따라 이루어졌다.

- 트레이너, FC는 회계, 통계 메뉴에 접근할 수 없다.
- 전역 데이터는 관리자만 접근 가능하다.
단, 실무 흐름에 따라 유연하게 해석한 부분도 있다. 예를 들어 트레이너는 기본적으로 자신이 담당한 회원에 대해서만 수업 관리 접근이 가능하지만, **회원 관리 메뉴에서는 모든 회원 정보를 조회**할 수 있도록 허용했다.

> 실무에서는 항상 FC가 상주해 있는 것이 아니기 때문에, 트레이너가 직접 회원의 상태를 변경하거나 출석, 예약 등을 처리할 수 있어야 한다. 현장 운영의 특수성을 고려한 예외적 권한 부여였다.

기본적으로 각 사용자는 업무 수행에 필요한 최소한의 메뉴와 기능만 노출되는 PoLP 원칙을 따른다. 트레이너, FC는 회계/통계 메뉴에 접근할 수 없다. 관리자 외에는 전역 데이터를 접근할 수 없다.

다만, 실제 운영 상황에 맞게 유연하게 해석되어 적용된 부분도 있었다. 예를 들어, 트레이너는 수업 관리 메뉴에서 담당한 회원에 대해서만 접근 가능하지만 회원 관리 메뉴에서 모든 회원 정보를 조회할 수 있다. 실무에서는 회원 데이터에 접근 가능한 직원이 항상 상주하지 않기 때문에 회원 상태 변경(홀딩/예약/출석 처리 등)을 처리할 수 있도록 트레이너에게도 권한이 부여되었다.
