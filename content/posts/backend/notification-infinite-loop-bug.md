## 같은 알림톡이 계속 나갔다

인톡 파트너스에는 관리자가 보낸 채팅을 사용자가 읽지 않으면 알림톡을 보내는 기능이 있다. 이 알림톡이 읽지 않은 사용자에게 끝없이 반복 발송되고 있었다. 3월 26일에 고쳤다.

## 원인은 TTL이 끝나는 것이었다

기존 로직은 이랬다.

1. 30분마다 크론이 돌면서 3시간 이상 미읽음인 채팅방을 찾는다.
2. 그 채팅방 사용자에게 알림톡을 보낸다.
3. 중복 발송을 막으려고 Redis에 `chat:unread-alimtalk:{roomId}`를 24시간 TTL로 저장한다.

24시간 동안은 막히지만, TTL이 끝나면 키가 사라진다. 사용자가 여전히 읽지 않았으니 다음 크론에서 조건이 다시 맞고, 알림톡이 또 나간다. 크론이 30분 단위라서 발송 시각이 매일 최대 30분씩 밀렸다.

```
Day 1: 10:00 발송 → TTL 만료: Day 2 10:00
Day 2: 10:30 크론 → TTL 만료됨 → 재발송 → 새 TTL: Day 3 10:30
Day 3: 11:00 크론 → TTL 만료됨 → 재발송 → 새 TTL: Day 4 11:00
```

읽지 않는 한 하루에 한 번씩 영원히 나가는 구조였다. 하고 싶었던 건 "한 번만 보낸다"인데 구현은 "하루 동안만 막는다"였다.

TTL을 늘리는 건 답이 아니라고 봤다. 사용자가 읽고 나서 새 메시지를 또 안 읽었을 때의 정상 알림까지 막히기 때문이다.

## TTL 대신 상태로

중복 방지를 시간이 아니라 상태로 바꿨다. 알림톡은 최대 2번이다.

```
[관리자 메시지 1시간 미읽음]
    → 리마인드 알림톡 발송 + 채팅방에 종료 예고 메시지
    → Redis: chat:unread-reminder:{roomId} (TTL 없음)

[종료 예고 후 1시간 미읽음]
    → 종료 안내 알림톡 발송 + 채팅방 자동 CLOSED

[사용자가 읽음]
    → 키 삭제 (처음 상태로)
```

```typescript
// 이전: 24시간 TTL
await this.redisService.set(`chat:unread-alimtalk:${room.id}`, '1', 60 * 60 * 24);

// 이후: TTL 없음. 읽으면 지운다
await this.redisService.set(`chat:unread-reminder:${room.id}`, 'sent');
```

종료 예고를 보낸 시각은 `chat:unread-closing:{roomId}`에 따로 저장해서 2단계 판단에 쓴다. 크론은 30분에서 10분 간격으로 줄였다. 미읽음 기준이 1시간이라, 30분 간격이면 알림이 최대 30분 늦게 나간다.

## 남은 것

원래 TTL 기반 코드는 2월에 전임자가 넣은 것이다. 이 수정으로 알림톡은 사용자당 최대 2번이 되고, 두 번째 알림톡과 함께 채팅방이 닫힌다. "최대 2번, 이후 채팅방 종료"라는 정책은 내가 정했고, 인톡 케어 개발자와 논의했다.
