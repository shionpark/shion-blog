## 이 글을 쓰는 이유

이력서에는 "데이터 분석가 → 프론트엔드 → 풀스택"이라고 한 줄로 적혀 있지만, 실제로는 각 전환마다 "이걸 왜 내가 직접 할 수 없지?"라는 질문이 있었습니다. 그 질문들이 쌓여서 지금의 포지션이 만들어졌습니다.

## 1단계: 데이터 분석가 — 숫자는 보이는데 바꿀 수 없었다

### 빅스인텔리전스 (2020.12 ~ 2022.04)

첫 직장은 데이터 분석·컨설팅 기업이었습니다. AI 기반 기업 미래성장지수 모델의 지표 산출 기준을 정리하고, NIA 공공 데이터 플랫폼 사업에서 데이터 제공 범위와 활용 시나리오를 정의하는 일을 했습니다.

이 시기에 배운 것은 **데이터를 구조화하는 힘**이었습니다. 흩어진 정보를 모아서 하나의 기준으로 정리하고, 그 기준이 의사결정에 쓰이는 과정을 경험했습니다.

### 미리디 (2022.05 ~ 2022.08)

디자인·인쇄 커머스 기업에서 키워드 광고 성과를 분석했습니다. 마케팅 퍼널 분석 쿼리를 작성하고, 광고 성과를 주문 데이터 기준으로 해석할 수 있도록 지표를 정의했습니다.

여기서 느낀 한계는 명확했습니다. **분석 결과를 보고서로 전달하면, 그것을 제품에 반영하는 건 다른 사람의 몫이었습니다.** "이 퍼널에서 이탈이 발생한다"는 것을 알아도, 직접 UI를 바꾸거나 로직을 수정할 수 없었습니다.

## 2단계: 프론트엔드 — 사용자 경험을 직접 만들 수 있게 되었다

### 코드잇 부트캠프 (2025.11 ~ 2026.01)

분석가로서의 한계를 느끼고, 프론트엔드 개발을 본격적으로 배우기 시작했습니다. React, TypeScript, Next.js를 집중적으로 학습하고, 팀 프로젝트(Run Fit)에서 실전 경험을 쌓았습니다.

### 비더라이트 컴퍼니 (2023.12 ~ 2025.04)

다지점 헬스장 운영 관리 시스템(Gymlight Manager)의 프론트엔드를 담당했습니다. 이 시기에 배운 것은 **컴포넌트 설계와 상태 관리의 실전 감각**이었습니다.

회원 상세 화면에서 갱신 주기가 다른 데이터를 한 번에 요청하면서 불필요한 리패칭이 발생하는 문제를 발견하고, 조회 시점을 분리해서 해결했습니다. 권한 로직이 여러 화면에 분산되어 있던 것을 하나의 기준으로 통합한 경험도 이때입니다.

프론트엔드를 하면서 새로운 질문이 생겼습니다. **"이 데이터는 왜 이렇게 내려오는 거지?"** API 응답 구조가 화면에 맞지 않을 때, 프론트에서 변환하는 것보다 백엔드에서 바꾸는 게 맞는 상황이 반복됐습니다.

## 3단계: 풀스택 — 흐름 전체를 책임진다

### 인톡 (2026.03 ~ 현재)

AI 기반 보험 전문가 교육 플랫폼에서 풀스택 개발자로 일하고 있습니다. Next.js + NestJS + PostgreSQL + Redis로 프론트엔드와 백엔드를 모두 담당합니다.

풀스택으로 전환하고 나서 가장 크게 달라진 점은, **문제를 발견하면 어디서든 고칠 수 있다는 것**이었습니다.

- 마케팅팀이 광고 성과를 감으로 판단하고 있다 → UTM 캠페인 분석 엔진을 직접 설계하고, Daily Briefing을 Slack으로 자동 발송하는 시스템을 구축
- 블로그 콘텐츠를 매일 수작업으로 만들고 있다 → Claude API로 콘텐츠 생성 파이프라인을 자동화
- 외부 보험 API와 연동이 필요하다 → Fernet 암호화, Redis 캐싱, 다단계 본인인증까지 직접 구현

분석가였을 때는 "이게 문제다"까지만 할 수 있었고, 프론트엔드였을 때는 "화면은 바꿨는데 데이터가..."였다면, 지금은 문제를 정의하고 해결까지 직접 끝낼 수 있습니다.

## 각 단계가 지금에 주는 영향

돌아보면 각 단계가 낭비가 아니라 축적이었습니다.

- **데이터 분석 경험** → UTM 분석 엔진을 설계할 때, 어떤 지표가 의미 있는지 바로 판단할 수 있었음
- **프론트엔드 경험** → 백엔드 API를 설계할 때, 프론트에서 쓰기 편한 응답 구조를 바로 만들 수 있음
- **두 경험의 교차** → "데이터가 수집되어 사용자에게 전달되기까지의 흐름 전체"를 설계하는 지금의 강점

## 마무리

커리어 전환은 리스크가 있지만, 각 단계에서 쌓은 관점은 사라지지 않습니다. 데이터를 구조화하는 능력, 사용자 경험을 설계하는 감각, 시스템을 직접 구축하는 기술 — 이것들이 합쳐져서 지금 제가 가장 잘 하는 일이 되었습니다.

비슷한 전환을 고민하는 분이 있다면, "지금 하는 일에서 어떤 질문이 반복되는가"를 살펴보시길 권합니다. 그 질문이 다음 단계를 가리키고 있을 수 있습니다.
