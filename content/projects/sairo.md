부산을 방문한 외국인 사용자에게 현장에서 가까운 장소를 추천하는 앱입니다. 4인 팀에서 앱 화면을 맡았습니다. 추천은 규칙 기반 엔진이고 AI 추천이 아닙니다.

## 맡은 일

- **추천 점수가 전부 0점** — 에러는 없는데 추천 장소 49곳이 모두 0점이었습니다. 진단 화면은 유형 코드를 `JSON.stringify`로 따옴표째 저장하고, 추천 엔진은 원래 문자열로 읽어 매칭에 실패하고 있었습니다. 이미 값이 저장된 기기가 있어서 저장 방식은 두고 읽는 쪽에서 두 형식을 모두 받도록 고쳤습니다.
- **오프라인 진단 안내와 예보 시각** — 에러 문자열 하나에 "진단 없음"과 "불러오기 실패"가 섞여 있어 타입으로 나누고 재시도를 붙였습니다. 최대 3시간 지난 예보를 지금 날씨로 보여 주던 문제는 예보 시각을 KST로 비교해 고쳤습니다.
- **저장 목록 공유** — 추천, 저장, 내 정보 세 화면이 같은 저장 목록을 쓰도록 `useSyncExternalStore` 기반 훅으로 묶었고, 렌더마다 돌던 `JSON.parse`를 저장·해제할 때만 돌게 했습니다.
- **접근성과 성능** — 흰 배경에서 2.68:1이던 보조 텍스트 대비를 7.4:1로 올리고, 한 화면에 13종이던 글자 크기를 6단으로 정리했습니다. 2.0MB 가변 폰트는 굵기 3벌 서브셋으로 줄였습니다.
- **다국어와 앱 빌드** — 외국인이 쓰는 화면이라 next-intl로 다국어를 붙였습니다. Capacitor 앱은 화면을 정적 export로 묶고 데이터는 배포된 API를 절대 경로로 부르는 구조로 만들었고, 폰트는 CDN 대신 로컬에 넣었습니다. 원스토어에 v1.1을 공개했습니다(2026-09-16).

## React Native 전환 스파이크 (2026.09 ~)

Cultural Fit Busan(SAIRO)의 Capacitor 앱을 React Native로 옮길 때 얼마나 드는지 확인하려고, 화면을 실제로 옮겨 보는 스파이크입니다. Android 에뮬레이터에서 실행해 검증했고 iOS는 실행하지 않았습니다. 상세 화면 이식과 저장 탭은 아직 하지 않았습니다. 코드는 [shionpark/sairo-rn](https://github.com/shionpark/sairo-rn)에 있습니다.

- **재사용 범위를 숫자로 확인** — 웹의 추천 엔진·타입·데이터 22개 파일 중 20개를 수정 없이 썼습니다(파일 91%, 줄 97%). 고친 2개 파일은 next-intl 의존과 화면 컴포넌트 타입 의존을 제거한 것입니다.
- **저장소 교체** — 웹은 동기 `localStorage`를 써서, 동기 API가 있는 MMKV를 골랐습니다. 원본 `storage.ts` 본문은 그대로 두고 18줄을 추가했고, 앱을 강제로 종료한 뒤에도 값이 남는 것을 확인했습니다. 네이티브 모듈이 Expo Go에서 돌지 않아 dev build(`expo run:android`)로 실행했습니다.
- **추천 훅과 API** — 3개 파일 257줄 중 6줄을 고쳤고, 운영 API 데이터로 웹과 22위까지 같은 순위가 나오는 것을 확인했습니다.
- **피드 화면** — 웹 화면 코드 10개 파일 735줄을 RN 436줄로 다시 썼습니다. 줄높이 배수, em 자간, CSS 변수, 그라데이션, 그림자 같은 CSS로 막힌 8가지를 RN 방식으로 바꿨습니다.
- **티켓·PR 단위 진행** — 티켓마다 브랜치를 만들고 요약·확인·측정을 적은 PR로 남겼습니다. PR 7건을 병합했고 리뷰어는 없었습니다.
