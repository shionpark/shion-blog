옷 이름이 아니라 분위기로 검색해 패션을 찾는 서비스입니다. 3인 팀이고 저는 8월 중순부터 프론트엔드와 앱 빌드를 맡았습니다.

## 맡은 일

- **웹·앱 공용 빌드** — 서버 컴포넌트와 ISR에 기대던 웹을 앱으로 감싸려면 정적 빌드가 되어야 했습니다. 기존 코드를 더 살릴 수 있는 Capacitor로 팀과 방향을 정하고, 서버 페이지 5개를 클라이언트 데이터 훅으로 바꾼 뒤 빌드를 웹과 앱 두 갈래로 나눴습니다. 네이티브 기능 호출은 플랫폼 분기로 감싸 웹 동작을 유지했고, iOS 시뮬레이터까지 실행했습니다(PR #7). 이후 앱에서 사진·옷 상세가 열리지 않는 문제가 나왔습니다. 정적 빌드는 경로를 미리 만들어야 하는데 사진 slug와 옷 id는 DB와 사용자 데이터라 미리 만들 수 없었습니다. 상세 페이지를 쿼리 파라미터 라우트로 바꾸고, 웹의 옛 주소도 같은 화면으로 열리게 남겼습니다(PR #31).
- **화면 개발** — 검색 페이지를 새로 만들고(PR #14), 탭바를 4개에서 2개로 줄이고 나의 공간을 8개 섹션에서 3개 블록으로 다시 구성했습니다(PR #13). 사진 업로드 화면은 Storage 저장까지 맡아 팀원의 태깅 API와 이어 전 구간을 실제로 돌려 확인했습니다(PR #19).
- **사진 속 아이템과 실제 상품 연결** — 사진 상세의 상품명이 캡션과 다르고, 누르면 쇼핑몰 검색 결과로 가는 문제가 있었습니다. 캡션에서 아이템을 뽑아 큐레이션한 뒤 DB에 넣는 스크립트를 만들어 사진마다 실제 상품을 연결했습니다(PR #29). 무드 상세의 더미 상품도 대표 코디의 실제 상품으로 바꾸고(PR #36) 다른 코디 썸네일 줄을 더했습니다(PR #37). 또 옷을 담을 때 출처 사진을 같이 저장해 코디 단위로 담고 보여 주게 했습니다(PR #32).
- **버그 수정** — `useSearchParams`에 Suspense 경계가 없어 프로덕션 상세 페이지 전체가 500이 나던 문제(PR #23), 정리 스크립트가 사용자가 올린 사진 행까지 지우던 문제(PR #24)를 고쳤습니다.
- **PR 리뷰** — 팀원 PR을 리뷰하면서 인증 없이 service key로 호출되던 API, 이미지 경로가 두 번 붙는 문제, DOM이 끝없이 늘어나는 목록을 찾았습니다. 팀원이 반영한 뒤 머지했습니다.
